# 关注功能测试指南

## 功能说明

关注功能允许用户关注其他用户，并在个人主页中查看：
- **粉丝**：关注该用户的用户列表
- **关注**：该用户关注的用户列表

## API 端点

### 关注/取消关注用户

**端点**：`POST /api/user/:username/follow`

**说明**：关注指定的用户。如果已关注，则取消关注。

**请求头**：
```
token: {当前登录用户的用户名}
Content-Type: application/json
```

**URL参数**：
- `username`: 要关注的目标用户名（或用户ID）

**响应示例**：

成功关注：
```json
{
  "code": 0,
  "message": "已关注用户 testuser456",
  "isFollowing": true,
  "targetUser": {
    "_id": "507f1f77bcf86cd799439011",
    "username": "testuser456",
    "nickname": "测试用户456"
  }
}
```

成功取消关注：
```json
{
  "code": 0,
  "message": "已取消关注用户 testuser456",
  "isFollowing": false,
  "targetUser": {
    "_id": "507f1f77bcf86cd799439011",
    "username": "testuser456",
    "nickname": "测试用户456"
  }
}
```

**错误响应**：

- 未提供token：`401` - `未提供认证令牌`
- 用户不存在：`401` - `用户不存在或令牌无效`
- 目标用户不存在：`404` - `目标用户不存在`
- 不能关注自己：`400` - `不能关注自己`

## Postman 测试步骤

### 前提条件

1. 确保后端服务器正在运行（`http://localhost:3000`）
2. 至少需要2个用户账号（用于测试关注功能）
3. 已导入 Postman Collection：`test/Postman-个人主页测试.postman_collection.json`

### 步骤1：准备测试用户

如果你还没有多个用户账号，需要先注册：

1. 使用 Postman 创建请求：
   - 方法：`POST`
   - URL：`http://localhost:3000/api/register`
   - Body（JSON）：
     ```json
     {
       "username": "user1",
       "password": "password123"
     }
     ```

2. 重复步骤1，创建第二个用户：
   - `username`: `user2`
   - `password`: `password123`

### 步骤2：设置 Collection 变量

1. 在 Postman 中，找到 **"个人主页测试"** Collection
2. 右键点击 → 选择 **"Edit"**
3. 切换到 **"Variables"** 标签页
4. 设置以下变量：
   - `username`: `user1`（当前登录用户）
   - `target_username`: `user2`（要关注的目标用户）

### 步骤3：测试关注功能

#### 3.1 关注用户

1. 在 Collection 中找到 **"5. 关注用户"**
2. 确保 URL 中的 `{{target_username}}` 已设置为 `user2`
3. 确保 Headers 中的 `token` 设置为 `{{username}}`（即 `user1`）
4. 点击 **"Send"** 按钮
5. 查看响应，应该看到：
   ```json
   {
     "code": 0,
     "message": "已关注用户 user2",
     "isFollowing": true,
     ...
   }
   ```

#### 3.2 验证关注关系

1. 调用 **"4. 获取个人主页"**，查看 `user1` 的个人主页：
   - URL：`{{base_url}}/api/user/user1`
   - 检查响应中的 `data.following` 字段，应该为 `1`（关注了1个用户）

2. 调用 **"4. 获取个人主页"**，查看 `user2` 的个人主页：
   - 修改 URL 为：`{{base_url}}/api/user/user2`
   - 检查响应中的 `data.followers` 字段，应该为 `1`（有1个粉丝）
   - 检查 `data.memesData.粉丝` 数组，应该包含 `user1` 的信息

#### 3.3 取消关注

1. 再次调用 **"5. 关注用户"**（使用相同的参数）
2. 查看响应，应该看到：
   ```json
   {
     "code": 0,
     "message": "已取消关注用户 user2",
     "isFollowing": false,
     ...
   }
   ```

3. 再次验证：
   - `user1` 的 `following` 应该变为 `0`
   - `user2` 的 `followers` 应该变为 `0`
   - `user2` 的 `粉丝` 数组应该为空

### 步骤4：测试粉丝列表

#### 4.1 创建多个关注关系

使用不同的用户账号，创建多个关注关系：

1. 用户A关注用户B
2. 用户C关注用户B
3. 用户D关注用户B

#### 4.2 查看粉丝列表

1. 调用 **"4. 获取个人主页"**，查看用户B的个人主页
2. 检查响应中的 `data.memesData.粉丝` 数组，应该包含用户A、C、D的信息：
   ```json
   {
     "memesData": {
       "粉丝": [
         {
           "id": "...",
           "username": "@userA",
           "nickname": "...",
           "avatar": "..."
         },
         {
           "id": "...",
           "username": "@userC",
           "nickname": "...",
           "avatar": "..."
         },
         {
           "id": "...",
           "username": "@userD",
           "nickname": "...",
           "avatar": "..."
         }
       ]
     }
   }
   ```

3. 检查 `data.followers` 字段，应该为 `3`

## 完整测试流程示例

### 场景：用户A关注用户B

```
1. 设置变量
   - username: userA
   - target_username: userB

2. 关注用户B
   POST /api/user/userB/follow
   Headers: token: userA
   → 响应: "已关注用户 userB"

3. 查看用户A的个人主页
   GET /api/user/userA

   GET /api/user/userB

   → 检查: memesData.粉丝 包含 userA

   POST /api/user/userB/follow
   Headers: token: userA
   → 响应: "已取消关注用户 userB"

6. 再次查看用户A的个人主页
   GET /api/user/userA
   → 检查: following = 0

7. 再次查看用户B的个人主页
   GET /api/user/userB
   → 检查: followers = 0
   → 检查: memesData.粉丝 为空数组
```

## 常见问题

### Q: 如何查看我关注的用户列表？

A: 调用获取个人主页API，查看响应中的 `data.following` 字段（数字）和 `data.memesData` 中的关注列表（如果有实现）。

**注意**：目前个人主页API只返回粉丝列表，不返回关注列表。如果需要查看关注列表，可以：
1. 查询当前用户的 `following` 字段
2. 或者在前端实现一个"关注"标签页

### Q: 如何知道是否已关注某个用户？

A: 调用关注API，查看响应中的 `isFollowing` 字段：
- `true`: 已关注
- `false`: 未关注

### Q: 关注功能会影响其他功能吗？

A: 不会。关注功能是独立的，不会影响：
- 模因的创建、收藏、点赞
- 用户个人信息的编辑
- 其他用户数据

### Q: 如何批量测试关注功能？

A: 可以使用 Postman 的 Collection Runner：
1. 创建多个请求，每个请求关注不同的用户
2. 使用 Collection Runner 批量执行
3. 查看结果统计
